# AI-verktygs-spaning — 25 november 2026

## Inledning

Veckans spaning har fyra tydliga underteman. Det första är *teamkoordination*: nu när enskilda agenter är vardagsmat börjar frågan om hur man organiserar ett *team* av agenter ta form — S.Space ger en gemensam arbetsyta, AI Context Flow MCP ett gemensamt minne. Det andra är *observability*: Appxiom kopplar live produktionsdata direkt in i agentens kontext, OpenSRE stänger loopen för serverincidenter och Dippr löser det fundamentala problemet att agenter och databaser inte delar affärsdefinitioner. Det tredje är *säkerhet*: Antelog sitter som en gatekeeper utanför alla konfigurerade agenter, gitroots lägger ett katalognivå-filter ovanpå GitHub. Det fjärde är *disciplin*: Superpowers ger Claude Code strukturerade arbetsmetoder med en installation, och seshka löser det irriterande problemet med processer som Claude lämnar kvar. Elva verktyg totalt.

## Gör Claude Code och andra AI-assistenter smartare

### Superpowers (obra) — metodologipaket som gör agenten mer disciplinerad

**Vad det är:** En samling skills (tillägg) för Claude Code och andra kodningsagenter som automatiskt tillämpar strukturerade arbetsmetoder — testdriven utveckling, debugging-protokoll, brainstorming och kodgranskning — utan att du behöver styra det manuellt.

**Varför det är intressant:** De flesta lägger skills till sin agent för att lägga till nya *verktyg* (Slack-integration, GitHub-access). Superpowers lägger istället till bättre *arbetsvanor*: skills aktiveras automatiskt när agenten gör relevanta uppgifter — debugging-skillen triggas när agenten stöter på ett fel, test-skillen triggas när ny kod skrivs. Det är som att ge Claude Code en erfaren handledare som ser till att agenten inte tar genvägar. Fungerar med Claude Code, Cursor, Codex, Gemini CLI och OpenCode — samma skill fungerar oavsett vilket kodningsverktyg man använder, utan att man behöver konfigurera om något.

**Buzz-nivå:** Håller på att bli en grej — +883 till +1 003 stjärnor per dag i vecka 47–48 (november 2026, agents-radar och gittok-aggregatorer). Stark och konsistent tillväxtsignal; exakt totalt stjärnantal varierar mellan aggregatorkällorna, verifiera mot repot.

**Testa:** https://github.com/obra/superpowers — installeras via Claude Code plugin marketplace.

### seshka — städa upp efter Claude Code utan att öppna terminalen

**Vad det är:** En gratis macOS-menyrad-app (öppen källkod) som visar och rensar processer och dev-servrar som Claude Code lämnat igång när sessionen avbröts.

**Varför det är intressant:** Claude Code startar processer — dev-servrar, databaskopplingar, bakgrundstjänster — men städar inte alltid upp dem när sessionen avslutas abrupt. Efter ett tag äter dessa "zombie-processer" minne och ockuperar portar, och det enda sättet att hitta dem är att gräva i terminalen. seshka identifierar exakt vilka processer Claude startade (via Claudes egna processmarkeringar) och låter dig avsluta dem med ett klick. Det är en enkel lösning på ett bekräftat och välkänt problem (#22448 i Claude Codes egna issues-spårare sedan februari 2026).

**Buzz-nivå:** Börjar fångas upp — 140 Product Hunt-upvotes 19 november 2026.

**Testa:** https://www.producthunt.com/products/seshka — gratis och öppen källkod, macOS.

### Antelog — stoppa farliga agentkommandon innan de exekveras

**Vad det är:** En runtime-säkerhetsvakt (gratis basnivå utan konto, macOS/Linux/Windows) som sitter utanför Claude Code och blockerar destruktiva kommandon — som att råka ta bort hela katalogen, committa lösenord till Git eller läcka API-nycklar — precis innan de exekveras.

**Varför det är intressant:** Claude Codes inbyggda godkännanderutor fungerar bra interaktivt, men under långa autonoma sessioner där agenten kör osenad är de lätta att missa. Antelog sitter som ett OS-lager utanpå *alla* konfigurerade agentverktyg under en gemensam policy, oavsett om du kör Claude Code, Cursor eller Codex — utan att du behöver ändra något i agenten. Jämfört med Bay AI (täckt 15 november 2026, som är enterprise-inriktat med matching prislapp) är Antelog riktat mot enskilda användare med ett gratis startläge och installation i ett kommando.

**Buzz-nivå:** Börjar fångas upp — lanserades ~14 november 2026 (Product Hunt), v0.9 med 27 releases vid lansering.

**Testa:** https://www.producthunt.com/products/antelog — gratis basnivå, installeras med ett kommando.

## Verktyg, automation & infrastruktur

### S.Space — gemensamt rum för dig, ditt team och era agenter

**Vad det är:** En delad arbetsyta från AutoGen-skaparna (AG2-teamet, ett av de mest använda multi-agent-ramverken) där mänskliga teammedlemmar och AI-agenter samsas i gemensamma rum — med delad minnesyta, agent-handoffs och tillgångskontroll per rum.

**Varför det är intressant:** Idag arbetar varje person med sin agent i isolering: din Claude Code-session, din kollegas Cursor-session. Om ni ska samarbeta måste ni manuellt kopiera kontext fram och tillbaka. S.Space ger ett koordinationslager: i ett gemensamt rum kan din agents arbete överlämnas sömlöst till din kollegas agent, med delat minne och tydlig ägarstruktur — rumägaren styr åtkomst, agentägaren behåller kontrollen över vilka handlingar agenten tillåts ta. Existerande multi-agent-ramverk (AutoGen, CrewAI) kräver att man kodar orkestreringslogiken; S.Space ersätter det med ett gränssnitt som liknar ett vanligt chattverktyg men där agenter är förstaklassiga deltagare.

**Buzz-nivå:** Håller på att bli en grej — 379 Product Hunt-upvotes 20 november 2026, #1 Product of the Week enligt ai-radar-digest.

**Testa:** https://www.producthunt.com/products/s-space

### Appxiom — agenten debuggar verkliga kraschar, inte hypotetiska

**Vad det är:** En integration som matar live produktionsdata (kraschar, felloggar, användarflöden som gick sönder) direkt in i Claude Codes arbetskontext för automatisk felsökning.

**Varför det är intressant:** Alla ledande AI-kodningsagenter ser bara källkoden — inte vad som faktiskt händer när koden körs av riktiga användare. Appxiom kopplar produktionsmonitoring (det som t.ex. Datadog och Sentry registrerar) direkt in i agentens kontext, så att agenten ser den faktiska krasch-stacken, sessionsdata och felfrekvens innan den börjar debugga. Det är skillnaden mellan "agenten gissar vad som kan ha gått fel" och "agenten ser exakt vad som gick fel, för vem och när." Liknande produktionsinsikt kräver idag manuell copy-paste från övervakningsverktyget till agentchansen.

**Buzz-nivå:** Börjar fångas upp — 289 Product Hunt-upvotes 19 november 2026.

**Testa:** https://www.producthunt.com/products/appxiom

### AI Context Flow MCP — ett delat minne för alla dina agenter och verktyg

**Vad det är:** En MCP-baserad delad minneslager som synkroniseras live över agenter, verktyg och teammedlemmar — en sorts "Google Doc för agentminne".

**Varför det är intressant:** Lösningar för agentminne som Letta (täckt 21 november 2026) är isolerade per verktyg: Claude Codes minne och Cursors minne lever åtskilt, och du kan inte dela minnet med en kollega. AI Context Flow MCP exponerar minnet som en MCP-resurs — det standardprotokoll som alla moderna kodningsagenter stöder — vilket innebär att *alla* agenter med MCP-stöd kan läsa och skriva till samma minne, oavsett om det är Claude Code, Cursor eller Codex. Du äger och styr vad som lagras. Det är i princip "ett versionshanteringsystem för agentminne" som hela teamet och alla verktyg delar.

**Buzz-nivå:** Börjar fångas upp — 241 Product Hunt-upvotes 23 november 2026.

**Testa:** https://www.producthunt.com/products/ai-context-flow

### Dippr — ge agenten affärsdefinitioner, inte råa databaskolumner

**Vad det är:** Ett semantiskt datalager som ger AI-agenter enhetlig, permissionstyrd tillgång till företagsdatalager (Snowflake, BigQuery, Redshift m.fl.) via naturligt språk — med konsekventa affärsdefinitioner som säkerställer att "intäkt" alltid betyder samma sak.

**Varför det är intressant:** När en AI-agent får direktaccess till ett företagsdatalager stöter den ofta på ett fundamentalt problem: kolumnnamn som `c_rev_q3_adj_fx` säger inget om vad de innehåller, och utan ett semantiklager kan två agenter som frågar "total intäkt Q3" råka få olika svar beroende på hur de väljer att summera data. Dippr löser det med ett meningslager: affärsbegreppet "intäkt" mappar konsekvent till rätt kolumner, och row-level permissions avgör vad varje agent faktiskt får se. Jämfört med befintliga semantiklager (dbt Semantic Layer, Cube) är Dippr byggt specifikt för agent-queries snarare än traditionella analytiska dashboardverktyg.

**Buzz-nivå:** Börjar fångas upp — 214 Product Hunt-upvotes 20 november 2026.

**Testa:** https://www.producthunt.com/products/dippr

### OpenSRE — agenten som utreder serverincidenter åt dig

**Vad det är:** Ett öppet ramverk (Apache 2.0, självhostat) för att bygga AI-agenter som automatiskt undersöker produktionsincidenter — hämtar kontext från CloudWatch, Sentry, Splunk eller Azure Monitor, korrelerar loggar och metrics och genererar en utredningsrapport med remediationsförslag direkt till Slack eller PagerDuty.

**Varför det är intressant:** Liknande agenter från AWS DevOps Agent och Azure SRE Agent kräver att man bor i deras respektive moln — de fungerar inte om man blandar tjänster. OpenSRE är molnagnostiskt med ett pluggbart provider-system som täcker 60+ integrationer. Driftsätts med `opensre investigate` och agenten tar sig igenom allt. Det stänger loopen på ett liknande sätt som Databricks Genie ZeroOps (täckt 23 november 2026) men för generell serverinfrastruktur istället för datapipelines.

**Buzz-nivå:** Börjar fångas upp — +450 GitHub-stjärnor per dag (agents-radar 22 november 2026), public alpha.

**Testa:** https://github.com/Tracer-Cloud/opensre — öppen källkod, Apache 2.0.

**Varför det är intressant:** Webbläsaragenter (Browser Use, Operator) är notoriska för att fastna halvvägs i komplexa webbflöden — formulär med flerstegsvalidering, inloggningar med tvåfaktorsautentisering, dynamiska gränssnitt. ### gitroots — ge agenten exakt rätt mapptillgång i ditt GitHub-repo

**Vad det är:** En proxy som lägger katalognivå-åtkomstkontroll ovanpå GitHub — definiera allow/deny-regler per katalogträd och filtyp som enforkas framför GitHub API och GitHub MCP-servern.

**Varför det är intressant:** GitHubs inbyggda behörigheter är antingen allt eller inget på repo-nivå — du kan inte nativt säga "agenten får läsa `/src/features/**` men inte `/infra/**` eller `*.env`". gitroots enforkar sådana regler som ett extra filterlager. Jämfört med GitRails (täckt 23 november 2026, som begränsar vilka *repos och API-endpoints* agenten når) är gitroots ett kompletterande lager som arbetar inuti ett repo på fil- och katalognivå — de två täcker olika delar av same problemet med att ge agenter minsta möjliga behörigheter.

**Buzz-nivå:** Extremt tidigt — 71 Product Hunt-upvotes 23 november 2026. Nisch-verktyg men adresserar ett strukturellt hål i agentsäkerheten.

**Testa:** https://www.producthunt.com/products/gitroots

## Specialgrejer & experiment

### PaperOrchestra — fem agenter skriver ett vetenskapligt manus åt dig

**Vad det är:** Googles multi-agent-system (Google Cloud AI Research) som förvandlar experiment-loggar och labb-anteckningar till ett konferensklart vetenskapligt manus — med separata agenter för disposition, figurskapande, litteratursökning, skrivning och förbättring.

**Varför det är intressant:** Verktyg som AI Scientist (Sakana AI) försöker köra hela forskningsloopen autonomt — idé, experiment, papper. PaperOrchestra fokuserar specifikt på manuskriptfasen, den del som tar mest tid efter ett experiment är klart. Fem specialiserade agenter arbetar parallellt: en söker litteratur (via Semantic Scholar), en planerar strukturen, en skapar figurer från rådata, en skriver sektionerna, en förbättrar texten. Projektet rapporterar 14–38 % bättre resultat mot autonoma baslinjer i parvis mänsklig utvärdering. Stöder CVPR- och ICLR-mallar.

**Buzz-nivå:** Håller på att bli en grej — 4 314 GitHub-stjärnor med +1 524 på en dag (gittok 19 november 2026), arXiv-preprint 2604.05018, täckt av AlphaSignal och Decrypt.

**Testa:** https://github.com/google-research/paper-orchestra — öppen källkod.
