# AI-verktygsspaning 2026-10-29

## Inledning

Veckans spaning fångar ett nytt skikt i agenternas infrastruktur: verktyg som hjälper dig att *hålla koll* på agenter har blivit lika viktiga som agenter själva. Fyra av tolv fynd är övervaknings- eller kontrollverktyg — ett tecken på att de som arbetar med AI-agenter dagligen nu möter ett nytt problem: inte att starta agenter, utan att hålla ordning på dem. Parallellt sticker ett nytt IDE från JetBrains ut med rekordsnabb tillväxt, byggt specifikt för agent-arbete.

---

## Topp 3 att testa direkt

**ThinkRail** — JetBrains nya öppna IDE låter agenter arbeta i isolerade kopior av kodbasen utan att störa varandra, med inbyggt projektminne som agenten läser vid varje ny session.

**Boat** — Ge dina agenter ett permanent hem: molnbaserade datorer som sparar all state mellan körningar, så agenten fortsätter exakt där den slutade.

**agentgateway** — En enda kontrollpunkt för all agenttrafik — hanterar säkerhet, kostnadsövervakning och routing till modeller, verktyg och andra agenter i ett system, med Linux Foundations stöd bakom.

## Gör Claude Code och andra AI-assistenter smartare

### ThinkRail (JetBrains)
**Vad det är:** Ett nytt öppet (Apache 2.0) IDE från JetBrains — bolaget bakom IntelliJ och PyCharm — byggt från grunden för att arbeta med AI-agenter parallellt, med inbyggd isolering och projektminne.

**Varför det är intressant:** Grundproblemet med parallella agenter är att de konkurrerar om samma filer — som fem personer som redigerar ett dokument utan versionshantering. ThinkRail löser det på systemnivå: varje agent får en helt isolerad kopia av kodbasen (en "worktree") och bär med sig ett `SPEC.md`-minnesdokument som berättar vad projektet gör och hur det är tänkt att fungera. Agenten läser detta vid varje ny session, vilket eliminerar den vanliga "vad höll vi på med förra gången?"-fasen. Skiljer sig från Cursor och Windsurf genom att isoleringen är inbyggd i IDE:n, inte ett externt skript som läggs till i efterhand.

**Buzz-nivå:** Håller på att bli en grej — 5 304 GitHub-stjärnor totalt, +3 679 på en vecka, +1 068 på en dag (2026-10-29). Ovanligt hög tillväxthastighet. Apache 2.0-licens.

**Testa:** https://github.com/JetBrains/thinkrail — gratis, kör som desktop-app eller via `thinkrail`-CLI i webbläsaren.

### ccmon
**Vad det är:** En liten övervakningsapp (gratis, öppen källkod) som visar i realtid vad Claude Code och dess underagenter gör — vilka tokens de förbrukar, vilken status varje deluppgift har och vad som händer just nu.

**Varför det är intressant:** Claude Codes inbyggda utskrift är linjär och svåröverskådlig när man kör komplexa uppgifter med många steg och parallella underagenter. ccmon lägger ett strukturerat lager ovanpå utan att ändra något i Claude Code — skillnaden liknar att titta på råa serverloggar kontra ett dashboard. Uppdateras var 0,5 sekund och kräver ingen konfiguration eller konton.

**Buzz-nivå:** Extremt tidigt — aktiv på PyPI och Homebrew, börjar spridas i Claude Code-communities.

**Testa:** https://pypi.org/project/ccmon/ — `pip install ccmon` eller `brew install ccmon`.

### Canopy
**Vad det är:** En gratis, öppen skrivbordsapp (Mac/Windows/Linux) som samlar alla dina agentsessioner i ett enda fönster med kostnadsspårning, kontextanvändning och en inbyggd webbläsare per arbetsgren — utan telemetri, utan konton.

**Varför det är intressant:** Vanliga terminallösningar ger noll synlighet i parallella agentsessioners kostnad eller hur nära kontextgränsen varje session är. Canopy ger det visuella lager som saknas: du ser direkt vilka sessioner som jobbar, vilka som väntar och vad de hittills kostat. Den inbyggda webbläsaren per arbetsgren sparar dessutom inloggningstillstånd per projekt, så agenten slipper logga in på nytt varje körning.

**Buzz-nivå:** Extremt tidigt — 174 GitHub-stjärnor. Gratis, ingen telemetri, inga betalplaner.

**Testa:** https://canopy.itsol.tech — Mac, Windows och Linux.

### lazyagent
**Vad det är:** En liten terminalapp + macOS-menyrad (Go, MIT) som läser sessioner från Claude Code, Cursor, OpenCode och Pi i realtid och visar dem i ett gemensamt gränssnitt — utan extensions eller konfigurationsändringar.

**Varför det är intressant:** Varje kodagent har sin egna session-UI och det saknas ett samlat läge. lazyagent samlar information från alla agenter på ett ställe utan sidoeffekter. Utöver terminalappen finns en iOS-kompanjonapp som ansluter till Mac-appens HTTP API — du kan övervaka dina agenter från telefonen medan de kör. Installeras med ett kommando via Homebrew.

**Buzz-nivå:** Börjar fångas upp — v0.7.2 mars 2026, iOS-app juni 2026, aktiv release-historik.

**Testa:** https://github.com/illegalstudio/lazyagent — `brew install lazyagent`

## Verktyg, automation & infrastruktur

### Boat
**Vad det är:** Molnbaserade, persisterande virtuella datorer (YC-backed) designade specifikt för AI-agenter — agenten kopplar upp, fortsätter precis där den slutade, och all state sparas permanent.

**Varför det är intressant:** Tillfälliga sandlådetjänster försvinner när körningen avslutas — allt agenten installerat, alla filer den skapat, är borta. Boat sparar hela tillståndet permanent: nästa gång agenten kopplar upp hamnar den i exakt samma miljö, med alla installerade paket och filer intakta. "Snapshot-forking" låter dig dessutom grena från ett känt tillstånd för att köra parallella varianter av samma uppgift — som git fast för hela datorns tillstånd. Stödjer Claude Code, Codex och OpenCode. Servrar i EU (Tyskland, Finland, Frankrike).

**Buzz-nivå:** Börjar fångas upp — YC-backed, lanserat oktober 2026. 7 dagars fri provperiod.

**Testa:** https://www.ycombinator.com/companies/boat — $20/mån, 7 dagars fri provperiod med 25 compute-timmar.

### agentgateway (Linux Foundation)
**Vad det är:** En öppen (Apache 2.0, Linux Foundation) Rust-proxy som kombinerar tre agentprotokoll i ett: routing till AI-modeller (LLM Gateway), routing till verktyg via MCP och routing mellan agenter via A2A.

**Varför det är intressant:** De flesta gateways hanterar ett protokoll åt gången — ett för modeller, ett för verktyg, ett för agent-till-agent-kommunikation. agentgateway behandlar alla tre nivåerna som ett enda system och lägger till säkerhet (rollbaserad åtkomst), kostnadsövervakning, rate limiting och fullständig loggning. Linux Foundations inblandning signalerar att detta siktar på att bli industristandard, likt hur Nginx en gång blev standard för webbservern. Stödjer Kubernetes och levereras med ett inbyggt UI.

**Buzz-nivå:** Börjar fångas upp — 5 743 GitHub-stjärnor, +259 den senaste veckan. Apache 2.0.

**Testa:** https://github.com/agentgateway/agentgateway — dokumentation på agentgateway.dev.

### Agent Beacon
**Vad det är:** Ett öppet (MIT) lokalt minneslager som spelar in och normaliserar sessioner från 20+ olika AI-kodningsagenter och delar funna lösningar med alla agenter via MCP eller Agent Skills.

**Varför det är intressant:** En felsökningspattern som en Claude Code-session löser kan automatiskt bli tillgänglig för nästa Cursor-session — utan att du kopierar något manuellt. Konkurrenter som mem0 och MemoryOS är bundna till en specifik agent. Beacon normaliserar sessionsdata tvärs alla agenter och har ett granskningssteg innan kunskap återanvänds, för att förhindra att felaktiga lösningar sprids vidare. All data stannar lokalt med en valfri moln-sync.

**Buzz-nivå:** Börjar fångas upp — 2 911 GitHub-stjärnor totalt, +560 den senaste veckan (Go trending, v.45 2026). MIT-licens.

**Testa:** https://github.com/Asymptote-Labs/agent-beacon

### Opengeni
**Vad det är:** En självhostbar, öppen (Apache 2.0) körningsmiljö för AI-agenter med inbyggt stöd för persistenta sessioner, felåterhämtning, isolerade sandlådor, behörighetshantering och mänskliga godkännandesteg.

**Varför det är intressant:** Ramverk som LangChain beskriver vad agenten ska göra — Opengeni är det som faktiskt *kör* den, hanterar krascher och sparar tillståndet. Tänk skillnaden mellan ett recept och ett kök: ramverket är receptet, Opengeni är köket. Teamet drev agenter mot riktig produktionsmiljö i CloudGeni i två år innan de open-sourcade kärnan. Kan köras som managed cloud (5 % pålägg på modellkostnaden) eller helt self-hosted för $0. Stödjer E2B, Daytona och Modal som sandlådemiljöer.

**Buzz-nivå:** Extremt tidigt — lanserades Product Hunt 6 oktober 2026, ~2 400 GitHub-stjärnor. Apache 2.0.

**Testa:** https://github.com/Cloudgeni-ai/opengeni — Railway one-click-deploy finns.

### ManyAgents
**Vad det är:** En macOS-app som samlar alla dina parallella AI-kodningsagenter — Claude Code, Codex — i ett enda fönster med en gemensam prioriterad kö för godkännanden och frågor.

**Varför det är intressant:** Att jonglera fem terminaler med varsin agent skapar kaos när de alla väntar på godkännande samtidigt — du ser inte vad som är akut och vad som kan vänta. ManyAgents samlar allt i en "Needs You"-kö sorterad efter prioritet. Appen stödjer specialiserade roll-baserade agenter (workers, thinkers, reviewers) och inkluderar en inbyggd iOS-simulator för att testa mobilappar direkt bredvid agentfönstret, utan att byta fönster.

**Buzz-nivå:** Börjar fångas upp — 102 röster på Product Hunt, lanserat 26 oktober 2026.

**Testa:** https://www.producthunt.com/products/manyagents

## Specialgrejer & experiment

### AWS Infinity
**Vad det är:** En öppen (Apache 2.0) körningsmiljö för AI-agenter, co-byggd av Amazon och UC Berkeley, som löser ett grundläggande effektivitetsproblem: agenter som väntar på svar blockerar idag datorresurser i onödan.

**Varför det är intressant:** Tänk dig ett callcenter där varje anställd bara kan ha ett pågående ärende åt gången — även om ärendet kräver tre timmars väntan på svar. Dagens agent-runtimes fungerar exakt så: en agent som väntar på ett API-svar håller en tråd blockerad. AWS Infinity "pausar" agenten helt under väntan och frigör resursen direkt — 75 000 vilande agenter i 8 GB RAM (benchmarkat med simulerad modell på en server). Det är en tidig forskningsrelease som pekar mot hur nästa generations agentruntimes kan se ut när man ska köra hundratals agenter parallellt till rimlig kostnad.

**Buzz-nivå:** Börjar fångas upp — annonserades 23 oktober 2026 av AWS Open Source Blog. Tidig forskningsrelease, inte en hanterad tjänst.

**Testa:** https://aws.amazon.com/blogs/opensource/introducing-infinity-a-runtime-for-extreme-agent-concurrency/

### GhostHands
**Vad det är:** Ett gratis, öppet (MIT, macOS Apple Silicon) verktyg som låter en liten lokal AI-modell styra native Mac-appar åt dig — via tillgänglighetsgränssnitt, utan att data streamas till molnet.

**Varför det är intressant:** Anthropics computer-use API — som låter Claude styra en dators gränssnitt — kräver molnet och kostar pengar per anrop. GhostHands kör 100 % lokalt på Apple Silicon med en komprimerad liten modell: noll latens, noll kostnad per anrop, noll data som lämnar maskinen. Du kan dessutom spela in ett flöde manuellt och spela upp det automatiskt utan att AI-modellen ens är inblandad — ren automation utan molnanrop. macOS 14+ krävs.

**Buzz-nivå:** Extremt tidigt — under 1 000 GitHub-stjärnor, nyligen lanserat (synkad circa 11 oktober 2026). MIT-licens.

**Testa:** https://github.com/georgenijo/ghosthands — Apple Silicon och macOS 14+ krävs.
