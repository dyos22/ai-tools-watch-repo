# AI-verktygsspaning — 1 oktober 2026

*Veckovis bevakning av nya och uppåtkommande AI-verktyg*

---

## Inledning

Veckans fynd kretsar kring ett problem som växer i takt med att AI-agenter jobbar mer självständigt: *hur vet man egentligen vad agenten håller på med?* Tre av veckans starkaste lanseringar adresserar just det — en arbetsyta som visar varför agenten ändrade koden, en live-whiteboard den ritar i under arbetets gång, och en app som samlar alla parallella agenter i ett enda samtal. Parallellt med det tar agent-native infrastruktur ett tydligt steg framåt: en databasklient byggd från grunden för MCP-integration och en headless webbläsare som kostar 16 gånger mindre att använda med agenter än vanlig Chrome. Det ekosystem som håller på att växa fram behöver inte bara fler agenter — det behöver verktyg för att förstå och styra dem.

## Gör Claude Code och andra AI-assistenter smartare

### WHITEBOARD — agenten förklarar varför, inte bara vad

**Vad det är:** En skrivbordsapp (öppen källkod, MIT, YC W26) för programmerare och AI-agenter som planerar och granskar kod i samma arbetsyta. Agenter (Claude Code, Codex) ritar automatiskt sekvensdiagram, databasmodellsdiagram och beslutsloggar av sina egna ändringar — du granskar dem i en strukturerad vy bredvid kodskillnaden.

**Varför det är intressant:** AI-genererad kod är svår att granska just för att agenten inte berättar *varför* den ändrade något — bara vad den ändrade. WHITEBOARD gör det konkret: en agent som lade till ett nytt API-anrop ritar flödet, en agent som refaktorerade en databasklass ritar modellen. Det kallas "cognitive debt" i AI-kodning — det ackumulerade underskottet av förklaringar du aldrig fått — och WHITEBOARD är det tydligaste försöket hittills att lösa det strukturellt snarare än med bättre promptning.

**Buzz-nivå:** Håller på att bli en grej — 330+ poäng och 120+ kommentarer vid Show HN-lansering 24 september 2026, ~1 000 GitHub-stars en vecka efter lanseringen.

**Testa:** https://github.com/devdotfast/whiteboard — skrivbordsdemo och installationsguide i README.

### TRACE-MCP — agenten förstår hela kodbaser utan att slösa tokens

**Vad det är:** En MCP-koppling (tillägg till Claude Code och liknande) som analyserar din kodbas och bygger en semantisk karta — ett beroendediagram — som agenten kan fråga med exakta symbolreferenser i stället för att läsa in råa filer. Förstår 48+ ramverk och 68 programspråk, och har 100+ verktyg för symbolnavigering, spårning av vad en ändring påverkar, och säkerhetsscanning.

**Varför det är intressant:** En stor kodbas innehåller kanske tiotusentals filer. Claude Code läser in dem ett efter ett tills kontextfönstret är fullt, och missar ändå ofta kopplingar. TRACE-MCP låter agenten fråga "vilka funktioner anropar `processOrder`?" och få ett exakt svar direkt i stället för att söka igenom tio filer för att ta reda på det. Projektet uppger 97 % färre tecken per utforskning — en enda fråga till kopplingen ersätter vad som annars tar ~42 minuters agentarbete. Det adresserar kontextfönster-ekonomin direkt, vilket är ett av de verkliga kostnadsproblemen för seriöst AI-assisterad kodning.

**Buzz-nivå:** Börjar fångas upp — 89 GitHub-stars (juli–september 2026). Listad i awesome-mcp-servers, Glama.ai och MCP Market. Plockas upp av Claude Code- och Codex-användare i communities.

**Testa:** https://github.com/nikolai-vysotskyi/trace-mcp — konfigurationsguide för Claude Code i README.

### DRAWGENT — rita arkitektur live med din AI-kodningsagent

**Vad det är:** Ett verktyg (Rust + JavaScript, öppen källkod) som kopplar din befintliga Claude Code-, Codex- eller OpenCode-installation till en live Excalidraw-whiteboard. Du skriver arkitekturinstruktioner i chattytan eller lämnar anteckningar direkt på canvasen — agenten redigerar diagrammet i realtid och markerar det klart när den är färdig.

**Varför det är intressant:** Arkitekturskisser bor normalt utanför kodbasen och är osynliga för agenten, som då jobbar utan karta. Med DRAWGENT kan samma agent som känner repot rita och uppdatera ett levande arkitekturdiagram synkat med kodändringarna. Det löser ett konkret gap som WHITEBOARD inte täcker: planering *innan* koden skrivs, snarare än granskning *efter*. Kräver ingen molntjänst.

**Buzz-nivå:** Extremt tidigt — lanserades 26 september 2026, nådde Hacker News förstasida inom ett dygn från första kodrad. Mycket få stars ännu.

**Testa:** https://github.com/yanndegat/drawgent — setup i README, ansluts till befintlig agentinstallation.

## Verktyg, automation & infrastruktur

### DBX — databasklienten som pratar direkt med din agent

**Vad det är:** En 20 MB cross-platform databasklient (Rust/Vue) som stödjer 100+ databaser — MySQL, PostgreSQL, SQLite, Redis, MongoDB, DuckDB, SQL Server med mera — med en inbyggd AI-assistent (Claude, GPT eller lokala modeller via Ollama) och en inbyggd MCP-server som ger Claude Code och liknande agenter direkt tillgång till alla dina kopplade databaser.

**Varför det är intressant:** Vanliga databasklienter (DBeaver, TablePlus) är byggda för mänskliga databasadministratörer. DBX är designat från grunden för att vara ett verktyg *agenter* använder: AI-assistenten genererar SQL med säkerhetskontroller innan körning, och den inbyggda MCP-servern exponerar alla konfigurerade databasanslutningar direkt till agenter utan extra installation. Hela klienten ryms i 20 MB — jämfört med DBeaver som kräver ett Java-paket på 200+ MB.

**Buzz-nivå:** Håller på att bli en grej — +1 133 nya GitHub-stars på enbart 1 oktober 2026. Total stjärnräkning rapporteras till 873–9 200 beroende på källa; aktiv diskussion om MCP + local AI på Reddit. Inga källor rapporterar mer än 10 000 stars.

**Testa:** https://github.com/t8y2/dbx — installatörer för Mac, Windows och Linux i README.

### Agent FM — en enda yta för alla dina pågående AI-agenter

**Vad det är:** En skrivbordsapp för Mac och Windows (Y Combinator S26) som samlar alla pågående kodningsagenter — Claude Code, Codex, OpenCode — i en gemensam gruppchatt. Agenterna delar uppdateringar, blockers och beslut i chatten; du övervakar och svarar från ett enda fönster. Inkluderar live-ljud och röst-till-text för hands-free övervakning.

**Varför det är intressant:** Den som kör flera parallella kodningsagenter idag jonglerar med separata terminalfönster och långa textloggar — ett manuellt övervakningsarbete som tar tid och kräver konstant uppmärksamhet. Agent FM samlar signalerna utan att kräva ändringar i hur agenterna körs, och röstläget gör det möjligt att övervaka medan man gör annat. Grundarna kommer från Meta Superintelligence Labs och Snowflake.

**Buzz-nivå:** Håller på att bli en grej — Y Combinator Summer 2026-backat, aktiv diskussion på toolradar.com och aiindigo.com. Nylig lansering, ännu ingen publik GitHub-repo.

**Testa:** https://www.ycombinator.com/companies/agent-fm — registrering för tidig tillgång via YC-sidan.

### Plasmate — den 50× snabbare webbläsaren för agenter

**Vad det är:** En agent-native headless webbläsare (Rust) som i stället för att rendera en hel webbsida konverterar HTML till ett strukturerat JSON-format som AI-agenter kan läsa direkt — utan renderingsmotor, utan grafisk återgivning, utan att kräva en Chrome-installation.

**Varför det är intressant:** AI-agenter som navigerar webben idag kör Chrome under huven (via Playwright). Chrome kräver 300+ MB RAM per flik och genererar enorma textmängder för agenten att processa. Plasmate löser det på tre fronter: 30 MB RAM i stället för 300+, 50× snabbare sidladdning, och 16,6× färre tecken för agenten att läsa — vilket direkt sparar kostnader och tid i varje agentanrop som behöver webbläsning. Har MCP-server och bibliotek för Rust, Python, Node.js och Go.

**Buzz-nivå:** Börjar fångas upp — listad på mcpservers.org, glama.ai och i OpenClaw:s skills-katalog. Aktiv indexering sedan mars 2026.

**Testa:** https://github.com/plasmate-labs/plasmate — installeras med `npm install -g plasmate` eller `pip install plasmate`.

### SkillKit — pakethanteraren som löser kakofonin av agent-skills

**Vad det är:** En öppen pakethanterare för AI-agent-skills (instruktionsfiler som lär agenter nya förmågor) som tar en skill skriven i ett format och automatiskt översätter och installerar den i alla 44+ agentformat — Claude Code, Cursor, GitHub Copilot, Gemini CLI, OpenCode med mera — med ett enda kommando.

**Varför det är intressant:** Att skriva en skill (till exempel "granska alltid säkerhet" eller "skriv alltid tester") och sedan installera den i alla sina agenter kräver idag manuell anpassning för varje agents eget format. SkillKit eliminerar det: skriv en gång, deploya överallt. Inkluderar en marketplace med 15 000+ färdiga skills och AI-driven skill-generering för anpassade arbetsflöden.

**Buzz-nivå:** Börjar fångas upp — 337–1 400 GitHub-stars sedan lansering februari 2026. Listad på Product Hunt och indexerad på SourcePulse. Marketplace på skillselion.com.

**Testa:** https://github.com/rohitg00/skillkit — pakethanteraren installeras med ett kommando; skill-marketplace indexerad i README.

## Specialgrejer & experiment

### SLayer — SQL-abstraktionslagret för agenter som inte kan din databas

**Vad det är:** Ett öppet semantiskt lager (Python, MIT) för AI-agenter och datateam där agenten beskriver vad den vill ha i affärstermer — "försäljning per region per kvartal" — och SLayer genererar rätt SQL mot din databas, utan att agenten behöver känna till tabellstrukturen.

**Varför det är intressant:** Stora AI-modeller skriver ofta felaktig SQL mot komplexa databaser — de gissar tabellnamn, missar joins och hanterar affärsregler inkonsekvent. SLayer lägger ett beskrivande lager ovanpå: agenten frågar efter affärsbegrepp, inte råa tabeller. Jämfört med etablerade semantiska lager (dbt, LookML) är SLayer byggt specifikt för agentanrop, med MCP-server, REST API, CLI och Python-bibliotek, och kräver inget bygge-steg.

**Buzz-nivå:** Extremt tidigt — 118 GitHub-stars, 14 forks (juli 2026). PyPI-paket publicerat. MCP-server indexerad på glama.ai.

**Testa:** https://github.com/MotleyAI/slayer — Python-installation och demo i README.

### onUI — annotera din webbapp för AI-agenten direkt i webbläsaren

**Vad det är:** En lätt webbläsarextension (Chrome, Edge, Firefox) plus en lokal MCP-brygga som låter dig rita och annotera element i ett webbgränssnitt, och sedan skickar en strukturerad beskrivning av vad som behöver ändras till din AI-agent — utan att appens källkod berörs.

**Varför det är intressant:** AI-agenter kan inte "se" ett användargränssnitt utan extra verktyg — de läser kod, inte skärmar. onUI låter dig visa agenten exakt vad och var: markera en knapp som sitter fel, skriv "flytta hit", och agenten får det som en precis instruktion. Helt lokal utan molnbackend, fungerar per webbläsarflik, kompatibel med Shadow DOM som blockerar många liknande alternativ.

**Buzz-nivå:** Extremt tidigt — 85 GitHub-stars. Listad på Glama.ai och MCP Servers org. Plockas upp i MCP-communities.

**Testa:** https://github.com/onllm-dev/onUI — extensionsinstallation och MCP-konfiguration i README.

### GLiNER2.5-Decide — snabb sorteringsmodell för agentpipelines, utan grafikkort

**Vad det är:** En 340 miljoner parametrar stor öppen klassificeringsmodell (Fastino) som svarar på en lista med frågor om ett textstycke på en gång — syfte, brådska, känsla, kategori — i stället för att ge ett textsvar. Körs på vanlig CPU utan grafikkort och returnerar ett strukturerat svar på 167 millisekunder.

**Varför det är intressant:** I en agentkedja finns massor av steg som egentligen inte behöver ett textsvar — "är det här ärendet akut?", "vilken avdelning gäller det?", "ska agenten eskalera?". Att skicka de frågorna till Claude eller GPT är som att anlita en författare för att fylla i ett formulär. GLiNER2.5-Decide slår modeller tre gånger så stora (inklusive JevK5 vid 57,5 % mot egna 60,1 %) och kräver inget GPU-kort — relevant för den som kör agentpipelines på vanlig serverhårdvara. Gratis att köra via öppen källkod.

**Buzz-nivå:** Börjar fångas upp — lanserad 24 september 2026. Rapporterad av Alpha Signal ("slår 1B-modeller på agentrouting med 340M parametrar"). Hosted API tillgänglig.

**Testa:** https://huggingface.co/fastino/GLiNER2.5-Decide — Python-integration dokumenterad i README; hosted API på agent.fastino.ai.
